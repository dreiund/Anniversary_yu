# 反馈⑦轮设计定稿（地图三件套 + 数据安全防御）

> 定稿 2026-08-09。方案页答案：1A / 2A / 3A；bug3 待真机确认（§四）。bug4 已随 b509c37 修复。

## 一、行前日程地点选点 + 「计划」钉（1A）

- 日程表单地点行从纯文字改为**地图选点**（PlacePickerSheet + PlaceResolver，与记忆/小本本同管线归并）；
  `CDPlanItem.place` 关系 P2 起就在 schema 里，**零 CloudKit 部署**。placeText 同步写名字兼容旧数据展示。
- 地图新筛选 chip `计划`：显示挂着**未结束见面**日程的地点；见面结束 → 钉自动从地图消失（数据保留）。
- 钉角标：行动蓝圆 `计`（与小本本墨圆 `本` 并列成簇，一地多源全显示）。
- 行前计划列表点地点文字（已关联真地点且有坐标时）→ 弹**临时小地图**（PlaceMiniMapSheet，共用组件），
  见面结束后仍可定位，不进地图页。

## 二、「记得做」钉（2A）

- 地图新筛选 chip `记得做`：显示挂着**未完成且对我可见**记得做的地点（隐私沿用小本本规则——
  对方的私密条目所在地点在我端隐形）；勾选完成 → 钉消失。角标：行动蓝圆 `做`。

## 三、按第几次见面筛选（3A）

- 类目 chips 行左端新增 Menu：`全部见面 ▾` / `第 n 次 ▾`（倒序列出全部见面）。
- 与类目筛选**叠加生效**（交集）；选定具体见面时只看该次记忆钉——小本本/计划/记得做钉隐藏，
  若当时停留在这三个筛选上自动回落 `全部`。取景沿用既定平滑规则。

## 四、数据安全防御（bug3 疑因，先行落地）

- **撤掉启动孤儿清扫**（反馈⑥引入）：真机首启 CloudKit 镜像导入顺序不保证，地点先于记忆到达的窗口
  会被误判孤儿、真删并把删除同步回云端——疑似真机「地图空钉」元凶。只保留本机删除操作后的清扫。
- 地点档案：无坐标地点（手输老数据）把「在地图中查看」换成提示 `该地点没有坐标 · 编辑记忆重新选点可补`
  （小地图对 0,0 坐标会飘到大洋上）。
- bug3 最终确认待用户真机二查：①牛肉饭→科达路→档案→在地图中查看 是否有钉；②老记忆的地点行是否还在。
